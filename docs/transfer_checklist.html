Verify the copy before trusting it. A 1.4 GB USB transfer can truncate silently. On the desktop, in PowerShell, in the folder where you copied it:

Get-FileHash castelnuovo-image.tar.gz -Algorithm SHA256

The hash must be exactly:

FF893903453EBC636B3CD8C8B62D29FF8B5E44B2CE6F3F1286F8EEC52D468089

PowerShell prints it in uppercase; the comparison is case-insensitive. If it differs, copy the file again — do not proceed.

5. Order of operations — do not reorder

  1. Install Docker Desktop + Git, write .wslconfig, restart.
  2. docker load -i <path>\castelnuovo-image.tar.gz
  3. Clone the repository and check out chapter7-castelnuovo.
  4. Run the verification — verify_environment.py, ~20 min. It must print PASS. Do not skip it.
  5. Run the smoke test — timehistory_castelnuovo.py --smoke, ~10 min. Two lines matter; see below.
  6. Only then, the full run, detached.

6. Two things to report back before the full run starts

(a) The conflict guard. The smoke test prints either conflict guard passed or ABORT: N node(s) are both tied and duplicated at a contact interface. If it aborts, stop and report it — it is an anticipated modelling conflict, not something to work around.

(b) The recorder check. Find the block --- recorder check after 5 steps --- and send back the list of any recorder marked EMPTY. The damage-output response names for this material could not be verified in advance; OpenSees writes an empty file instead of raising an error, so a 30-hour run could otherwise finish with no damage data at all.
Expected run time: roughly 15–40 hours for the 19.5 s window (3900 steps). The first progress line of the transient gives a real estimate for that machine. The setup stages before it — meshing, then 20–60 minutes building one damage material per element — are normal and not a hang.

The 8 cores will not speed this up: the solver is sequential. And there is no restart — if the run is interrupted it begins again from zero, so disable Windows automatic restarts and sleep first.

After copying the image to the desktop, delete castelnuovo-image.tar.gz from the laptop Desktop — that drive is at 97% capacity.
